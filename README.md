# TDK Ecommerce Example (Vue + Hono)

[![Uses TDK CLI](https://img.shields.io/badge/Uses-TDK%20CLI-blue?style=flat-square&logo=github)](https://github.com/flisk-sh/flisk)

A small, complete [TDK](https://github.com/flisk-sh/flisk) project: a **Vue 3** storefront and a **Hono** catalog API, two resources of one `store` stack. It is the smallest example of opting into the Vue provider with `tdk resource --framework vue`.

`storefront-web` (Vue + Vite + TypeScript) shows a product grid with search, a cart, and checkout. `catalog-api` (Hono on Bun, in-memory) serves products and creates orders, pricing them in integer cents and refusing to oversell. No database is needed.

> **Requires TDK CLI 1.3.75 or newer** ([flisk#149](https://github.com/flisk-sh/flisk/pull/149) added Vue support). Older releases ignore `"framework": "vue"` and would generate React config for these files. Check with `tdk resource --help | grep -- --framework`.

## Run it


> **Repository-pinned CLI (optional):** Run `bun install` from the repository root to install the version pinned in `package.json`. Use `bun run tdk:project` to initialize project config, `bun run tdk:dry-run` to preview startup, or `bun run tdk:up -- <stack>` to start a stack. The global npm and standalone binary installation paths remain available.

Prerequisites: Docker running, [Tilt](https://docs.tilt.dev/install.html), [Bun](https://bun.sh/docs/installation) and the [TDK CLI](https://github.com/flisk-sh/flisk#installation).

```bash
git clone https://github.com/flisk-sh/tdk-ecommerce-example.git
cd tdk-ecommerce-example
tdk up store
```

| Resource | Type | Stack | Port | URL |
| --- | --- | --- | ---: | --- |
| [`catalog-api`](services/store/catalog-api) | Hono API | `store` | 4300 | http://api.tdk-ecommerce-example.localhost/api/catalog/api/products |
| [`storefront-web`](services/store/storefront-web) | Vue 3 app | `store` | 3300 | http://app.tdk-ecommerce-example.localhost/storefront-web |

Both go through Traefik; TDK does not publish the container ports on `localhost`. `tdk networks` lists the `*.localhost` routes; `tdk down` stops everything.

## How it was made

```bash
mkdir tdk-ecommerce-example && cd tdk-ecommerce-example
tdk project --yes
tdk resource catalog-api --type backend --stack store
tdk resource storefront-web --type frontend --framework vue --stack store
```

`--framework vue` writes `"framework": "vue"` into `storefront-web/service.json`. That single field makes TDK generate the Vue Vite config (`@vitejs/plugin-vue`) and a TypeScript config without React's JSX setting, into `.autogenerated/`. Docker, nginx, Traefik and Tilt are shared with React frontends.

Resources live under `services/<stack>/<name>/` because that is where `discovery.paths` in `.tdk/project.json` looks. `tdk resource` picks that folder for you and tells you when it does.

## Where to look

- [`catalog-api/src/index.ts`](services/store/catalog-api/src/index.ts): `GET /api/products?q=`, `GET /api/products/:id`, `POST /api/orders` (atomic stock check, 409 when short) and CORS, since the Vue app calls the API from its own origin.
- [`storefront-web/src/App.vue`](services/store/storefront-web/src/App.vue): the UI. [`cart.ts`](services/store/storefront-web/src/cart.ts) holds the cart rules and [`api.ts`](services/store/storefront-web/src/api.ts) the typed client, both unit tested.
- `service.json` in each resource is the whole TDK contract. `storefront-web` declares `dependsOn: ["catalog-api"]`.

> [!IMPORTANT]
> Edit `service.json` or the sources. Never edit `.autogenerated/`; TDK regenerates it.

## Test each resource

```bash
cd services/store/catalog-api && bun install && bun run test
cd ../storefront-web && bun run test && bun run build
```

`bun run build` runs `tsc && vite build --config .autogenerated/vite.config.build.autogenerated.ts`, the same command the Docker image runs. The config file appears after the first `tdk up` (or `tdk config regenerate`).
